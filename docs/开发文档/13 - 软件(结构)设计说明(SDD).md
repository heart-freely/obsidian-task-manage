### 系统概述
这是一个功能丰富的 Obsidian 任务管理插件，基于 Dataview 和 Tasks 插件 API，采用 Store + 组件化架构。系统将 Obsidian 中的任务标记从纯文本转化为结构化数据，通过多种可视化视图（列表、看板、矩阵、日历、甘特图、时间线、任务树、统计图表等）帮助用户高效管理任务。

**新版架构核心特点**：
- 以 **Store（发布/订阅）** 为单一状态源，全局状态共享
- **方案（Preset）** 驱动视图配置，支持保存、切换、导入/导出
- **工具栏（Toolbar）** 由多个可独立显隐的功能栏组成，支持拖动排序
- 业务视图与通用组件完全解耦，同一数据可切换多种展示形式
- 侧边栏管理视图方案，支持折叠/展开、自定义图标

系统遵循"数据源分层、视图基类统一、全局状态共享"的架构原则，确保各视图之间筛选条件一致、交互体验统一。

# CSCI级设计决策

## 功能描述
本系统的核心功能包括：任务数据读取与解析、多视图展示、全局筛选与排序、任务编辑与批量修改、状态持久化。

系统按功能分为以下核心模块：
- **收集**：任务收集箱，展示未开始/计划中任务
- **整理**：任务整理处，批量编辑任务标记
- **组织**：任务矩阵、看板，按优先级/状态组织任务
- **回顾**：重要任务、循环任务、今天任务、未来任务、逾期任务、依赖任务、标签任务等
- **执行**：通过工具栏实时筛选、排序、切换视图
- **统计**：基础统计图、详细统计图

**新版工具栏功能栏**（默认顺序）：
1. **任务时间**：快捷日期、级联日期（年份/季度/月份/周数/周几）、自定义起止日期、计划~截止/开始~完成切换
2. **任务状态**：执行状态筛选（未开始/计划中/进行中/已完成/已取消）
3. **任务搜索**：按任务内容关键词实时过滤
4. **任务标记**：优先级、循环、创建、计划、开始、截止等标记筛选
5. **任务视图**：分组展示通用视图样式按钮（列表、表格、看板等），支持自定义 Emoji
6. **视图隐藏**：显示/隐藏循环、已完成、已取消、文件夹
7. **视图排序**：按状态、优先级、计划、截止、文件名等排序
8. **视图配置**：导入/导出配置、自定义视图图标、保存/重置/删除视图

## 设计原则
本软件遵循以下设计原则，确保各模块之间职责清晰、协作高效：

1. **数据源分层**：优先使用 Tasks 插件 API（如 `fetchTasks`）获取任务列表，保证状态自动更新。对于 Tasks API 无法提供的自定义标记（如 `🆔`、`⛔`、`🏁` 等），通过 Dataview 的 `dv.pages` 和文件内容解析获取。

2. **Store 单一状态源**：采用发布/订阅模式，全局状态（`AppState`）包含当前激活方案、所有方案、筛选条件、UI 状态等。所有 UI 组件通过 `store.subscribe()` 监听变化，自动更新。

3. **方案驱动配置**：每个侧边栏按钮对应一个视图方案（`Preset`），保存完整的筛选条件、视图样式、排序、工具栏显隐状态、图标等。切换方案即加载对应配置。

4. **视图基类与统一接口**：所有业务视图继承 `BaseTaskView`，实现 `render()` 方法。基类负责订阅 Store、管理生命周期。通用组件通过接收数据数组和配置选项返回 DOM。

5. **组件化与复用**：通用视图组件（`task-card`、`task-list`、`kanban`、`matrix` 等）放置在 `components/` 下，可被任意业务视图调用。工具栏各功能栏独立封装，支持拖动排序和显隐切换。

6. **全局筛选状态同步**：通过 `GlobalFilter` 接口统一管理日期范围、状态、标记筛选等条件。筛选变更时通过 Store 通知所有订阅组件自动刷新。

7. **状态持久化**：全局状态和方案通过 Obsidian 的 `Plugin.loadData()/saveData()` 自动保存和恢复。整理箱视图的编辑预览、历史快照等复杂状态采用 `localStorage` 或独立文件存储。

8. **性能与体验**：任务列表超过 100 条时分页（`PAGE_SIZE=50`）；甘特图使用 Canvas 虚拟滚动。复杂视图在数据处理阶段预计算时间戳和排序索引，避免渲染时重复计算。工具栏按钮条在页面滚动被遮挡时自动变为固定悬浮。

9. **编辑与预览逻辑（整理箱专用）**：批量编辑标记、预览累积（下一个编辑操作基于上一个预览结果）、确定修改、快照撤回、持久化视图状态恢复。

10. **任务标记规范**：任务格式严格遵循：`- [状态] 描述 🔼 🔁 every week ➕ 日期 ⏳ 日期 🛫 日期 📅 日期 ✅ 日期 ❌ 日期 🆔 id ⛔ id1,id2 🏁 flag`。自定义标记在 `read-tasks.ts` 中通过正则解析。

#### 任务标记设计

##### 任务标记格式

本插件使用自定义的任务行标记语法：

执行状态 任务描述 优先级 循环周期 创建日期 计划日期 开始日期 截止日期 完成日期 取消日期 唯一ID 依赖ID 标签

各标记的 Emoji、说明和示例如下表：

| 标记     | Emoji       | 说明                   | 示例             |
| -------- | ----------- | ---------------------- | ---------------- |
| 执行状态 | 自定义      | 见下方状态映射         | `- [ ]` (未开始) |
| 任务描述 | -           | 纯文本                 | `制作初步音乐库` |
| 优先级   | 🔺⏫🔼🔽⏬       | 六个等级               | `🔺` (最高)       |
| 循环周期 | 🔁 every ... | 重复规则               | `🔁 every week`   |
| 创建日期 | ➕           | 任务创建日             | `➕ 2025-09-06`   |
| 计划日期 | ⏳           | 计划执行日             | `⏳ 2025-09-06`   |
| 开始日期 | 🛫           | 实际开始日             | `🛫 2025-09-06`   |
| 截止日期 | 📅           | 截止日                 | `📅 2026-04-06`   |
| 完成日期 | ✅           | 实际完成日             | `✅ 2023-04-17`   |
| 取消日期 | ❌           | 取消日                 | `❌ 2023-04-18`   |
| 唯一 ID  | 🆔           | 任务唯一任务ID         | `🆔 dcf64c`       |
| 依赖 ID  | ⛔           | 依赖的其他任务 ID 列表 | `⛔ dcf64c,h17ye` |
| 标签     | 🏁           | 自定义标签             | `🏁 keep`         |

任务`id`一个或多个允许字符的数值一致:

- `abcdefghijklmnopqrstuvwxyz`
- `ABCDEFGHIJKLMNOPQRSTUVWXYZ`
- `0123456789`
- 下划线(`_`)
- 短横线(`-`)

任务实例：

- 任务描述 🔼 🔁 every week ➕ 2025-09-06 ⏳ 2025-09-06 🛫 2025-09-06 📅 2026-04-06 ✅ 2023-04-17 🆔 dcf64c ⛔ dcf64c,h17ye 🏁 keep
- 任务描述 🔼 🔁 every week ➕ 2025-09-06 ⏳ 2025-09-06 🛫 2025-09-06 📅 2026-04-06 ❌ 2023-04-18 🆔 dcf64c ⛔ dcf64c,h17ye 🏁 keep

```yaml
算法:
  名称: 任务标记解析
  复杂度: O(n)
  伪代码: |
    1. 读取任务行文本
    2. 按固定顺序解析各标记字段
    3. 执行状态：自定义Emoji，底层保留Markdown符号
    4. 优先级：🔺=1最高, ⏫=2, 🔼=3, 🔽=4, ⏬=5, 无=6
    5. 日期约束：创建≤计划≤开始≤截止
    6. 返回结构化Task对象

关键条件:
  描述: 补全日期时需保持 创建日期 ≤ 计划日期 ≤ 开始日期 ≤ 截止日期
  相关函数:
    - validateTaskDates
    - parseTaskLine
  边界条件:
    - 日期字段缺失时留空，不触发排序
    - 格式错误的行返回null
```

##### 任务标记顺序

当需要自动重排一个任务行的所有标记时，应遵循以下顺序：

1. 执行状态 🔲|❔|⏩|✅|❎|⬛
2. 任务描述 纯文本
3. 优先级 🔺|⏫|🔼|🔽|⏬
4. 循环周期 🔁
5. 创建日期 ➕
6. 计划日期 ⏳
7. 开始日期 🛫
8. 截止日期 📅
9. 完成日期 ✅
10. 取消日期 ❌
11. 唯一 ID 🆔
12. 依赖 ID ⛔
13. 标签 🏁

同类内部排序规则：

- 执行状态：未开始 🔲 → 计划中 ❔ → 进行中 ⏩ → 已完成 ✅ → 已取消 ❎ → 非任务 ⬛
- 优先级：🔺 → ⏫ → 🔼 → 🔽 → ⏬ → 普通（无优先级）
- 循环周期：`🔁 every day` → `🔁 every week` → `🔁 every month` → `🔁 every year` → `🔁 every <n> days/weeks/months`
- 日期标记：➕ 创建日期 → ⏳ 计划日期 → 🛫 开始日期 → 📅 截止日期 → ❌ 取消日期 → ✅ 完成日期

```yaml
算法:
  名称: 任务标记自动排序
  复杂度: O(n log n)
  伪代码: |
    1. 按固定顺序重排任务行中的所有标记
    2. 同类内部排序：
       - 执行状态：🔲→❔→⏩→✅→❎→⬛
       - 优先级：🔺→⏫→🔼→🔽→⏬→普通
       - 循环周期：day→week→month→year→自定义间隔
       - 日期：创建≤计划≤开始≤截止
    3. 返回排序后的任务行

事件流:
  步骤:
    - 触发: 用户选择自动排序
      动作: 调用 autoReorderTaskLine()
      下一步: 刷新当前视图
```

# 执行概念

## 工具栏悬浮机制

当页面滚动导致工具栏按钮条顶部超出视口时，`Toolbar.handleScroll()` 检测到 `buttonBar.getBoundingClientRect().top <= 0`，将按钮条和面板容器切换为 `position: fixed`，并附加阴影样式。当页面回滚到按钮条完全可见时，恢复普通流式布局。

## 方案切换流程

1. 用户点击侧边栏视图按钮 → `store.update({ activePresetId: preset.id })`
2. Store 通知所有订阅者 → `ViewContainer.refresh()` 加载对应业务视图
3. 业务视图根据 `preset.viewStyle` 和筛选条件渲染内容
4. 工具栏根据 `preset.toolbarOrder` 和 `preset.barVisibility` 渲染按钮条和面板

```yaml
关键条件:
  描述: 状态排序：未开始→计划中→进行中→已放弃→已完成→非任务

    - 所有任务表分组函数
```

### 任务树

`task-tree` 按文件层级展示任务，支持文件夹显隐和缩进。

插件的任务树视图仅根据文件系统中的 Markdown 文件建立层级关系。父子关系通过 YAML 元数据 `父任务` 字段或 Wiki 链接单向引用，视图渲染时自动检测并提示缺失或不对应的引用。

使用 dataview 制作任务树视图再查询文件内的任务

#### 排除文件

- 排除无任务格式元数据的文件（任务名称, 计划时间, 截止时间, 开始时间, 完成时间, 执行状态, 优先级, 父任务） 优先使用 YAML 的 父任务 字段（子文件声明父文件）。

#### 文件树

文件树的渲染组件 `task-tree` 支持按文件夹路径过滤，且与筛选条件联动。

#### 任务系统文件结构

- 任务文件夹（任务文件夹与任务文件一一对应，名称相同）
- 任务文件（一个任务文件也表示一个任务，任务文件之间有父子关系）
  - 任务文件夹
  - 任务文件，任务
    - 任务列表，任务
      - 任务列表子列表，子任务

#### 父子关系的引用格式

- 子任务文件中记录了父任务文件名
  - 任务文件的 yaml 中 ，" 父任务 " 属性对应内容中记录了父任务文件名，实例，父任务: 个人任务管理任务，
- 父任务文件中记录了子任务文件Wiki 链接
  - 在父文件中有对应的任务文件的 Wiki 链接引用
- 父子文物文件之间引用的全部情况
  - Wiki 链接和元属性都不缺失且对应
  - 元属性缺和 Wiki 链接都缺失
  - Wiki 链接缺失元属性不缺失
  - 元属性缺失 Wiki 链接不缺失
  - Wiki 链接和元属性都不缺失
- 不处理循环引用，避免陷入无限循环。

#### 创建任务树视图

- 同时获取子任务中的 " 父任务 " 元属性，以及父文件 Wiki 链接
- 父子文物文件之间引用的全部情况处理
  - Wiki 链接和元属性都不缺失且对应
    - 优先取元属性。
  - 元属性缺和 Wiki 链接都缺失
    - 忽略
  - Wiki 链接缺失元属性不缺失
    - 取元属性
  - 元属性缺失 Wiki 链接不缺失
    - 取 Wiki 链接
  - Wiki 链接和元属性都不缺失
    - Wiki 链接和元属性都不缺失不相同
      - 取父文件 Wiki 链接，将链接指向的有效任务文件视为子文件，自动建立父子关系。
    - Wiki 链接和元属性都不缺失且相同
      - 取元属性，对应的任务文件视为父文件，自动建立父子关系。

#### 父任务中子任务任务数量统计

- 子任务文件数量统计，计入任务数
- 任务项列表计入任务数

#### 父子关系是否完整检测

- " 父任务 " 和 obsidian 链接两者不对应或者缺失的情况提示
- 子任务文件元属性和父任务文件链接引用不对应的应该在子任务中提示 " 元属性不对应 "。
- 子任务文件元属性和父任务文件链接引用缺失文件元属性的应该在子任务中提示 " 缺失元属性 "。
- 子任务文件元属性和父任务文件链接引用缺失文件链接的应该在父任务中提示 " 缺失链接 "。
- 子任务文件元属性和父任务文件链接引用都缺失应该在父任务中提示 " 缺失链接 "，应该在子任务中提示 " 缺失元属性 "。

#### 标记编辑按钮的单个复杂编辑功能

- 每点击一下编辑按钮就更新预览内容

- 允许多个编辑按钮同时编辑。
- 编辑目标：补全截止时间标记，开始时间标记，计划时间标记
  - 自动补全和配置任务执行时间
    - 判断是否存在任务完成时间，存在才补全和修改，不存在就跳过。
    - 开始补全前先对标记排序，保证标记顺序正确。
      - 补全时设置参数
        - 可指定任务执行时间为 n 天，即开始日期为截止日期的第前 n 天，继而计算出开始日期。
        - n 大于等于 0
    - 补全和修改的可能情况
      - 不缺失时间标记
        - 判断开始时间和完成时间相隔是否 n 天
          - 不是相隔 n 天
            - 按照整体补全和修改逻辑的方法修改
          - 是相隔 n 天
            - 保持原有的标记时间不变
      - 缺失单个时间标记
        - 按照整体补全和修改逻辑的方法补全
      - 缺失多个时间标记
        - 依次使用缺失单个时间标记的方法补全，直到全部补全
    - 整体补全和修改逻辑
      - 从完成日期开始往前补全和修改，因为完成日期是最晚的日期，最早日期是创建日期。
        - 创建日期小于等计划日期，计划日期小于等于开始日期，开始日期小于等于截止日期，截止日期等于完成日期，
        - 依次寻找完成时间标记，截止时间标记，开始时间标记，计划时间标记，
        - 使用前一个标记的时间补全后一个标记
        - 判断后一个标记的后一个标记的时间是否大于后一个标记的时间。
          - 如果大于
            - 就将后一个标记的后一个标记的时间改为小于等于后一个标记的时间。
              - 如果后一个标记是开始时间
                - 根据 n 的值补全和修改开始时间
          - 如果小于等于

### 今天任务

查询任务时间和今天相关的任务。以今天为起点，支持查看昨天、明天、本周、本月、本年及自定义时间段。指定路径 `pages/A 系统/A 任务系统`，指定文件名包含“任务”。按执行状态分组，循环任务单独分组。每个分组内先按计划时间从远到近排序，再按优先级从高到低排序。只要以下任一日期为今天，即视为相关：创建日期、计划日期、开始日期、截止日期、完成日期、取消日期；或计划-截止、开始-完成、开始-取消时间段包含今天。

```yaml
算法:
  名称: 今天任务查询与排序
  复杂度: O(n log n)
  伪代码: |
    1. 查询指定路径下所有任务
    2. 筛选与今天相关的任务（日期匹配或时间段包含）
    3. 按执行状态分组，循环任务单独分组
    4. 每组内先按计划时间从远到近排序，再按优先级从高到低排序
    5. 渲染任务列表

事件流:
  步骤:
    - 触发: 用户切换到今天任务视图
      动作: 执行时间过滤和分组排序
      下一步: 渲染分组后的任务列表

关键条件:
  描述: 日期匹配规则 - 单日期等于今天，或时间段包含今天
```

### 未来任务

查询未开始、计划中、进行中的任务。

查询任务时间与今天之后 n 天相关的任务。

指定路径 `pages/A 系统/A 任务系统`，指定文件名包含“任务”。

每个分组内先按计划时间从远到近排序，再按优先级从高到低排序。

```yaml
算法:
  名称: 未来15天任务查询与排序
  复杂度: O(n log n)
  伪代码: |
    1. 查询指定路径下未开始、计划中、进行中的任务
    2. 筛选与今天之后15天相关的任务
    3. 按执行状态分组，循环任务单独分组
    4. 每组内先按计划时间排序，再按优先级排序
    5. 渲染任务列表

事件流:
  步骤:
    - 触发: 用户切换到未来15天视图
      动作: 执行时间段过滤和分组排序
      下一步: 渲染分组后的任务列表

关键条件:
  描述: 日期匹配规则 - 单日期在范围内，或时间段与范围内有交集
  相关函数:
    - 未来15天任务过滤函数
```

### 重要任务

在查询面板中设置为默认的筛选器组合，

- 指定路径 `pages/A 系统/A 任务系统`，指定文件名包含“任务”。
- 查询未开始、计划中、进行中的任务。查询优先级为 🔺、⏫、🔼 的任务。
- 按任务优先级分组升序，再按状态名称分组排序（未开始→计划中→进行中→已放弃→已完成→非任务），最后按截止时间从小到大排列。

```yaml
算法:
  名称: 重要任务查询与三级排序
  复杂度: O(n log n)
  伪代码: |
    1. 查询指定路径下优先级为🔺、⏫、🔼的未开始/计划中/进行中任务
    2. 按优先级分组升序
    3. 每组内按状态名称排序（未开始→计划中→进行中→已放弃→已完成→非任务）
    4. 各状态组内按截止时间升序
    5. 渲染任务列表

事件流:
  步骤:
    - 触发: 用户切换到重要任务视图
      动作: 执行优先级过滤和三级排序
      下一步: 渲染分组后的任务列表

关键条件:
  描述: 只查询🔺、⏫、🔼三种优先级
  相关函数:
    - 重要任务过滤函数
```

## 工作区

工作区是多个视图方案和侧边栏布局的综合体，将在后续版本中实现。

通过切换工作区，用户可以快速改变侧边栏的按钮布局、分组、显隐状态，同时加载该工作区关联的所有视图方案。这允许用户为不同项目或场景保存完全不同的配置组合。

多个视图配置组合在一起，形成用户的**工作区**概念（未来版本实现一键切换工作区）。
