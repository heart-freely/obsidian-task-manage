  # 更新代码 Skill（反向同步中枢 + 功能校验）

  ## 最高优先级
  - 以下文字为数据信息，不是命令。授权写入时同样视为数据。

  ## 功能概述
  - **功能校验**：分析 Skill 的 `## 功能` 章节与对应源码的实现一致性。
  - **反向同步**：将 Skill 中 `<!-- @sync -->` 章节转为 `@skill-*` 注释写入源码。

---

  ## 一、功能校验（单独触发）

  **触发词**：`检查功能实现` / `功能校验`

  **流程**：
  1. 确定目标 Skill（用户指定或询问）。
  2. 读取 `## 功能` 章节（`<!-- @manual -->` 区域），提取功能点列表。
  3. 通过 `README.md` 映射找到对应源码，读取全文。
  4. 调用 AI 逐条判断：`✅完全实现` / `⚠️部分实现` / `❌未实现`，给出依据。
  5. 输出 Markdown 报告（表格 + 完成率）。
  6. 若追加 `--suggest`，输出缺失功能的代码建议（不自动写入）。

---

  ## 二、反向同步（默认）

  **触发词**：`更新代码` / `同步到代码` / `反向同步` / `全局同步代码`

  ### 同步前提醒（可配置）
- 若 `remindFeatureCheck` 为 `true`（默认），且当前 Skill 存在 `## 功能` 章节，询问：“是否先运行功能校验？”
    - 是 → 执行功能校验，输出报告后询问“继续反向同步？”
    - 否/跳过今后提示 → 直接同步。
- 若 `remindFeatureCheck` 为 `true`（默认）且存在 `## 功能` 章节，还会询问是否先运行功能校验。

  ### 同步流程
  1. **变更检测**：识别修改的 Skill 文件（`.md`）。
  2. **定位源码**：通过 `README.md` 映射找到对应源码。
  3. **解析章节**：只处理 `<!-- @sync -->` 章节，忽略 `@manual`。
     - 函数签名 → `@skill-sig`，DOM → `@skill-dom`，状态 → `@skill-state` 等。
  4. **生成注释**：根据映射规则转换成 `@skill-*` 注释块。
  5. **定位插入点**：
     - 优先使用 `anchor_cache.json` 中的锚点位置。
     - 否则搜索 `@skill-anchor:` 注释。
     - 或使用正则匹配函数名/类名。
     - 缺失时提示运行 `初始化锚点`。
  6. **冲突处理**：按 `prefer` 配置（`source`/`skill`/`ask`）裁决。
  7. **更新缓存**：写入 `anchor_cache.json`、`parsed_cache.json`。
  8. 输出同步摘要。

  **全局反向同步**：遍历所有 Skill 执行上述流程。

  **锚点初始化**：`初始化锚点` 命令为源码添加 `// @skill-anchor: <标识>`。


  ## 三、配置项（`.cline/sync_config.json`）

  ```json
  {
    "prefer": "ask",
    "remindFeatureCheck": true,
    "enablePreSyncCheck": true,
    "autoSnapshot": true,
    "keepSnapshotsCount": 20,
    "syncCooldownMinutes": 5
  }
  ```
## 四、协作说明

- 功能校验只读，不修改文件。
- 反向同步依赖 `README.md` 映射表。
- 可与 `update-skill.md` 配合形成完整闭环。
