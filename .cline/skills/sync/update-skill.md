# 更新技能 Skill（全功能同步中枢）

本 Skill 统一管理 Skill 文件的**创建、增量更新、全量结构同步**。

| 模式 | 触发词 | 说明 |
|------|--------|------|
| **增量更新** | `更新技能`、`同步技能`、`同步到文档` | 仅同步本次对话修改过的源码 |
| **全量同步** | `全局同步`、`校验技能` | 扫描全部源码，对齐结构与内容 |
| **自动创建** | 以上所有模式中，若 Skill 文件缺失，均会自动创建 | 确保一对一映射 |

---

## 一、核心原则

**源码目录结构决定 Skill 目录结构**  
映射规则：
- `src/panel/views/xxx-view.js` → `.cline/skills/code/views/xxx-view.md`
- `src/panel/bars/xxx-bar.js` → `.cline/skills/code/bars/xxx-bar.md`
- `src/tasks/process/xxx-process.js` 等核心业务逻辑文件 → 其设计要点统一记录在 `.cline/skills/code/skill.md` 中（各子模块的描述在架构 Skill 内按小节组织）

**全部 Skill 文件均可被修改**  
不再区分“手动维护区”和“自动更新区”。所有章节（包括架构总览、错误处理约定等）均可通过源码注释、头部信息或对话指令进行更新。同步工具仅从代码提取客观信息，不凭空修改设计意图；涉及主观决策时，会提示用户确认。

**自动创建时**，如果中间目录（如 `code/views/`、`code/bars/`）不存在，则递归创建。

---

## 二、增量更新（默认）

### 触发条件
本次对话中有 `write_to_file` / `edit_file` 操作，用户说 `更新技能`。

### 执行流程
1. **收集变更文件**  
   从对话历史中提取修改过的源码文件路径。
2. **映射 Skill 路径**  
   根据上述映射规则确定目标 Skill 文件。
3. **对于每个目标 Skill 文件**：
   - 如果 Skill 文件**不存在**，则进入「自动创建」流程（见第四部分）。
   - 如果存在，读取源码头部注释、所有 `@skill-*` 标签以及新修改的函数签名等，**全面更新** Skill 的对应章节。
4. **更新范围**：所有章节均可更新，包括：
   - 功能、实现方式
   - 核心函数、DOM 结构、状态模型
   - 事件流、数据流伪代码、算法复杂度
   - 错误处理与边界情况（若源码中有 `@skill-condition` 或相关注释）
   - 样式与主题适配细节（若源码中有 `@skill-dom` 或注释描述）
   - 测试要点（若源码中有测试相关注释）
   - 依赖、对外导出、公共 API
5. **保留原则**：如果源码中无相关信息，则保留 Skill 中已有的文字描述，不删除。
6. **输出更新摘要**，列出每个被更新的 Skill 及章节。

---

## 三、全量同步

### 触发条件
用户说 `全局同步` 或 `校验技能`。

### 执行流程
1. **收集所有源码文件**  
   遍历 `src/panel/views/*.js`、`src/panel/bars/*.js`，以及 `src/tasks/process/`、`src/tasks/read/`、`src/tasks/write/` 下所有 `.js` 文件。
2. **收集现有 Skill 文件**  
   遍历 `.cline/skills/code/views/*.md`、`.cline/skills/code/bars/*.md`、`.cline/skills/code/skill.md` 等。
3. **结构对齐**：
   - 源码存在但 Skill 缺失 → 自动创建 Skill 文件。
   - 源码已删除但 Skill 仍存在 → **提示用户**，询问是移至 `trash/` 还是 `archive/`，经确认后执行。
   - 文件名不一致（源码重命名导致） → **提示用户**，询问是否重命名 Skill 文件，经确认后执行。
4. **内容同步**：
   对每个 Skill 文件，读取对应源码的最新信息（头部注释、`@skill-*` 标签、函数签名等），**全面更新**所有章节。更新规则同增量更新。
5. **主架构 Skill 同步**：
   - 若核心模块（`read-tasks.js`、`write-tasks.js`、`common-process.js` 等）的函数签名或数据模型发生变更，同步更新 `code/skill.md` 的对应章节（如公共函数签名、Task 对象结构等）。
   - 若代码中新增了全局范围内的 `@skill-*` 注释（如 `@skill-dataflow`、`@skill-condition`），也会同步到架构 Skill 的相应位置。
   - ⚠️ 所有对 `code/skill.md` 的写入操作均视为关键操作，必须遵循「五、关键操作需人工确认」的规则。
6. **生成全量报告**，列出所有新建、更新、待确认的操作。

## 四、自动创建 Skill 文件

当增量更新或全量同步发现 Skill 文件不存在时，执行以下创建流程：

1. **确定目标路径**  
   例如源码文件为 `src/panel/views/dashboard-view.js`，则目标 Skill 为 `.cline/skills/code/views/dashboard-view.md`。  
   如果中间目录不存在，则先创建目录。

2. **生成 Skill 内容**  
   新建的 Skill 文件必须包含：
   - **标准 YAML 头部**  
     `name` 和 `description` 用中文描述视图功能（从源码头部注释提取或根据文件名推断）；`triggers` 包含默认触发词，再加 `更新技能`、`全局同步` 等通用触发词。
   - **固定章节骨架**  
     ```markdown
     # 仪表盘视图 Skill
     ## 文件
     src/panel/views/dashboard-view.js
     ## 功能
     （从源码头部注释提取）
     ## 实现方式
     （待补充）
     ## 核心函数
     （从 @skill-sig 或 export 提取）
     ## DOM 结构
     （从 @skill-dom 提取）
     ## 状态模型
     （从 @skill-state 提取）
     ## 事件流
     （从 @skill-flow 提取）
     ## 数据流伪代码
     （从 @skill-dataflow 提取）
     ## 关键算法复杂度
     （从 @skill-complexity 提取）
     ## 公共调用
     （从 @skill-api 或 import 提取）
     ## 关键条件
     （从 @skill-condition 提取）
     ## 错误处理与边界情况
     （如有相关注释则填入）
     ## 依赖
     （从源码 import 提取）
     ## 修改指南
     （待补充）
     ## AI 命令
     （待补充）
     ## 原始设计信息（原文，无修改）
     （待补充）
    ``` 
## 五、关键操作需人工确认

- **修改主架构 Skill (`code/skill.md`)**：任何对该文件的章节新增、修改、删除操作，都必须先向用户展示完整的 diff 或变更摘要，并等待用户明确同意后方可写入。
- **修改 `sync/` 目录下的任何 Skill 文件**：这些文件控制着整个同步、快照、恢复流程的行为。任何对其内容的修改（无论是通过对话指令还是自动同步触发），都必须先向用户展示完整的变更摘要，并等待用户明确同意后方可执行写入。
