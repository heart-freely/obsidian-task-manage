# 更新代码 Skill（反向同步中枢）

读取 Skill 文档中的章节信息，**同步到对应的源码注释**（`@skill-*` 标签），为正向同步提供闭环。

**映射规则**（共用 `.cline/skills/README.md`）

---

## 反向同步核心流程

### 一、增量反向同步（默认）

**触发词**：`更新代码`、`同步到代码`、`反向同步`

**流程**：

1. **检测变更文件**：使用 `git status` 和缓存识别本次修改的 Skill 文件。
2. **定位目标源码**：从 README.md 获取映射。
3. **解析 Skill 变更章节**：只处理 `<!-- @sync -->` 或默认章节，忽略 `@manual`。
4. **生成注释内容**：根据映射表（函数签名→`@skill-sig` 等）转换。
5. **定位源码插入点**：
   - 优先使用 `.cline/skills/cache/anchor_cache.json` 中的锚点位置。
   - 若无缓存，扫描源码查找 `@skill-anchor:` 或使用正则启发式匹配（函数名、类名）。
   - 若仍找不到，提示用户运行 `初始化锚点`。
6. **更新源码注释**：替换锚点所在注释块，或插入新注释。
7. **冲突处理**：若配置 `prefer` 为 `"source"` 或 `"skill"`，则自动按配置覆盖；若为 `"ask"`（默认），则暂停并交互。
8. **更新缓存**：将新位置写入 `anchor_cache.json` 和 `parsed_cache.json`。
9. 输出预览并请求确认（除非自动仲裁）。

### 二、全局反向同步

**触发词**：`全局同步代码`

遍历所有 Skill，执行反向同步，重建缓存。

### 三、锚点管理

**触发词**：`初始化锚点`、`添加锚点`、`修复锚点`

扫描源码，根据函数名、类名生成锚点注释 `// @skill-anchor: <标识>`，插入函数前或类顶部，更新缓存。

---

## 冲突仲裁配置

读取 `.cline/skills/cache/sync_config.json` 中的 `prefer` 字段：
- `"source"`：冲突时自动保留源码注释。
- `"skill"`：自动以 Skill 文档覆盖源码注释。
- `"ask"`（默认）：生成报告并询问用户。

---

## 关键操作需人工确认

- 修改任何源码文件。
- 删除或覆盖现有注释（若 `prefer` 非自动覆盖）。
- 全局反向同步。

---

## 协作说明

- 反向同步，正向由 `update-skill.md` 负责。
- 缓存共享。
