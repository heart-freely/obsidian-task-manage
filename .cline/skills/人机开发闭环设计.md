# 编码与文档双向同步闭环系统设计方案 v3.1（最终融合版）

> **适用环境**：VSCode + Cline Chinese + DeepSeek API + 工程师  
> **核心理念**：以 Skills（Markdown 文档）为设计真相，源码注释为技术细节；AI 负责同步与转换，人工负责设计决策与审核。  
> **当前能力**：基于四个核心 Skill（`update-comment`、`update-skill`、`update-code`、`update-snapshots`）实现全功能闭环，**无需额外工具**。  
> **本版优化**：缓存验证、冲突自动仲裁、快照联动细化、非视图章节精简、性能可视化、统一命令入口。

---

## 一、双向变更嗅探与增量同步机制

### 1.1 设计目标
自动检测源码或 Skill 文档的变更，仅同步修改部分，减少人工操作和 token 消耗。

### 1.2 当前实现

| 能力     | 实现方式                                                     |
| -------- | ------------------------------------------------------------ |
| 变更检测 | 执行 `git status --porcelain` 获取变更文件列表，维护 `.cline/skills/cache/sync_state.json`（记录上次 commit hash 及每个文件的修改时间戳）。若无 Git，则对比文件 mtime。 |
| 增量同步 | 只处理变更的 hunk（通过 `git diff` 获取），仅将差异部分发送给 DeepSeek 解析。 |
| 批量合并 | 多个小变更合并为一次 API 调用（AI 分析时自动合并）。         |
| 手动触发 | 用户通过 `更新技能`、`同步到代码`、`反向同步` 等命令触发；也可使用统一入口 `同步`。 |

**标记规范**：
- `<!-- @manual -->`：人工维护章节（如 `## 功能`），AI 同步时自动跳过。
- `<!-- @sync -->`：可由 AI 从源码同步覆盖的章节。
- 无标记章节：默认可同步，冲突时需人工确认。
- `## 修改指南` 采用追加模式：AI 可在末尾追加新条目（格式：`YYYY-MM-DD: 内容`）。

**版本契约**：Skill 文件头部增加 `skill-version: 3.1`，若版本低于当前，执行自动格式迁移（保留所有内容，调整章节顺序）。

### 1.3 缓存有效性增强

- 缓存文件 `parsed_cache.json` 中每个条目存储 `mtime`（文件修改时间）和 `hash`（内容简短校验）。
- 同步前检查文件实际 mtime 是否与缓存一致，若不同则重新解析并更新缓存。
- 缓存目录：`.cline/skills/cache/`。

### 1.4 轻量级升级选项（可选）

- **正则启发式匹配**：在锚点缺失时，基于函数名、类名的正则表达式自动定位插入位置。
- **增量缓存**：对解析过的 `@skill-*` 注释位置持久化，避免重复解析。

## 二、正向同步：源码 → Skill（`update-skill.md`）

### 2.1 设计目标
从源码中的 `@skill-*` 注释、头部信息、JSDoc 等提取信息，同步到 Skill 文档，确保设计文档与代码一致。

### 2.2 当前实现

| 能力     | 实现方式                                                     |
| -------- | ------------------------------------------------------------ |
| 信息提取 | 解析源码头部、`@skill-*` 标签、JSDoc（`@param`、`@returns`），提取函数签名、DOM、状态、流程、依赖等。 |
| 结构对齐 | 全量同步时扫描 `src/` 下所有业务文件，自动创建/删除/重命名 Skill 文件（需用户确认）。 |
| 内容更新 | 严格遵循 `@manual`/`@sync` 标记：跳过人工章节；`## 修改指南` 追加新条目（不覆盖原有）。 |
| 自动校验 | 检查 YAML 头部、`@see` 有效性、章节结构，自动修复格式问题。  |
| 依赖提示 | 读取 `README.md` 中的 `depends_on`，更新后输出影响列表。     |

**设计决策自动记录**：当用户对话中明确做出设计决策（如“将优先级映射改为 p0→Q2”），AI 生成待确认修改：更新对应 Skill 的 `## 功能`（仅建议，不自动写入），同时将该决策写入当前快照的“关键决策”部分。用户批准后执行。

### 2.3 非视图模块章节精简

自动创建 Skill 时，根据源码特征智能省略不适用的章节：
- 若无 `render()` 或 DOM 操作 → 不生成 `## DOM 结构`。
- 若无内部状态变量 → 不生成 `## 状态模型`，仅写 `/* @skill-state 无 */`。
- 若无复杂算法 → 不生成 `## 关键算法复杂度`。

## 三、反向同步：Skill → 源码（`update-code.md`）

### 3.1 设计目标
允许用户直接修改 Skill 文档，系统自动将变更反写到源码的 `@skill-*` 注释中，实现双向闭环。

### 3.2 当前实现

| 能力          | 实现方式                                                     |
| ------------- | ------------------------------------------------------------ |
| 映射规则      | 基于 `.cline/skills/README.md` 的映射表。                    |
| 章节→标签映射 | 函数签名→`@skill-sig`，DOM→`@skill-dom`，状态→`@skill-state` 等。 |
| 精确插入      | 优先使用缓存中的锚点位置，或扫描 `@skill-anchor:` 注释。若缺失，使用正则启发式匹配（函数名、类名），或提示运行 `初始化锚点`。 |
| 冲突处理      | 检测到双方修改时生成冲突报告，交互解决。                     |
| 增量/全量同步 | 支持 `更新代码` 和 `全局同步代码`。                          |

### 3.3 反向同步冲突仲裁规则（可配置）

在 `.cline/sync_config.json` 中添加：
```json
{
  "prefer": "source"   // 可选 "source" | "skill" | "ask"
}
```
- 若设置为 `"source"`：当冲突时自动保留源码注释，不询问。
- 若设置为 `"skill"`：自动以 Skill 文档为准覆盖源码注释。
- 若设置为 `"ask"`（默认）：交互式询问。

## 四、结构自动对齐系统

### 4.1 设计目标
当源码文件增删重命名时，自动维护 Skill 文件及映射表（`.cline/skills/README.md`）。

### 4.2 当前实现

| 事件       | 实现方式                                                     |
| ---------- | ------------------------------------------------------------ |
| 新增文件   | 全量同步时检测到新文件，提示创建对应 Skill（自动生成模板，含精简章节），并询问添加到 README.md。 |
| 删除文件   | 列出对应 Skill，询问移至 `archive/` 或删除。                 |
| 重命名文件 | 通过 `git status` 检测到 `renamed:`，提示用户更新 Skill 文件名和映射。 |
| 依赖维护   | 在 README.md 中手动或通过命令更新 `depends_on`。自动分析 `import` 和 `extends` 生成建议列表。 |

## 七、快照管理联动（`update-snapshots.md`）

### 7.1 设计目标
在同步前后自动保存对话快照，支持回滚，实现连续开发上下文恢复。

### 7.2 当前实现

| 能力           | 实现方式                                                     |
| -------------- | ------------------------------------------------------------ |
| 同步前自动快照 | 在 `update-skill` 和 `update-code` 执行前调用 `保存快照`。   |
| 回滚命令       | `撤销同步` 读取最近快照，恢复修改过的文件列表（依赖 git 或备份）。 |
| 快照内容       | 包含对话摘要、修改文件清单、关键决策、下一步计划、对话分段。 |
| 快照索引       | `.cline/skills/snapshots/index.json` 记录所有快照元信息，支持快速检索。 |

### 7.3 快照→Skill 联动细化

命令 `从快照更新 Skill`：
1. 读取最新快照（或用户指定），解析其中的“关键决策”列表。
2. 对于每条决策，提取涉及的 Skill 名称（约定格式：`涉及 Skill：xxx`）。
3. 将决策内容追加到对应 Skill 的 `## 修改指南` 末尾（格式 `YYYY-MM-DD: 决策内容`）。
4. 输出预览，用户确认后写入。

### 7.4 轻量级升级选项

- **快照自动清理**：保留最近 20 个，自动删除更早的（可配置）。
- **细粒度回滚**：支持回滚单个文件。

## 八、成本控制与性能优化

### 8.1 当前实现

| 策略             | 实现方式                                                     |
| ---------------- | ------------------------------------------------------------ |
| 仅同步 diff hunk | 通过 `git diff` 获取变更块，仅传输差异部分。                 |
| 自动同步冷却     | 在 `update-skill.md` 中检查距上次同步时间，若小于 5 分钟且无重要变更则跳过。 |
| 静默模式         | 用户说“开启静默模式”后，AI 只记录变更不主动同步。            |
| 性能监控         | 记录每次同步的 token 消耗和耗时，超阈值（token>5000 或耗时>10s）输出警告，数据写入 `.cline/sync_perf.log`。 |

### 8.2 性能可视化

命令 `查看同步性能`：AI 读取 `.cline/sync_perf.log`，生成 Markdown 报告，包含：
- 最近 10 次同步的平均耗时、平均 token。
- 最耗时的操作类型。
- 优化建议（如“考虑拆分大文件”）。

### 8.3 轻量级升级选项

- **增量缓存**：将解析过的 `@skill-*` 位置缓存，避免重复解析。
- **请求合并**：多个小变更合并为一次 API 调用（通过提示词引导）。

## 九、高级特性

### 9.1 自举验证
`sync/` 下核心 Skill（`update-skill`, `update-code`, `update-snapshots`, `update-check`, `update-version`, `update-self`）自身遵循注释规范，映射到 `sync/sync-meta.md`。命令 `验证自身` 检查规范符合度并生成元文档。

### 9.2 统一命令入口（总控 Skill）
新增 `sync.md`（可选），触发词 `同步`，AI 自动判断方向：
- 若本次对话修改了源码 → 执行 `更新技能`。
- 若修改了 Skill → 执行 `更新代码`。
- 若两者都有 → 先执行 `更新代码`，再 `更新技能`。
- 用户可追加参数：`同步 --full`（全量）、`同步 --check`（巡检）。

- 将未完成任务按优先级自动分入四个象限
